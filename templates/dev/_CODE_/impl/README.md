# <코드> Impl — 진행 관리

## 시작하기 — 이 단계 세션 진입점
> ⚠️ 새 항목은 산출물 전에 플랜 모드로 플랜을 작성·검수·승인받는다.

읽는 순서: 1 이 README → 2 `progress.md` · `open-questions.md` · (있으면) 루트 `handoff.md` → 3 `checklist.md` → 4 관련 설계(`../design/map.md` · 단위 설계 · `dev/global/`)

현재 브랜치가 `dev/README.md` 표의 진행 중 사이클 브랜치(`cycle/<코드>`)인지, 사이클 README의 "현재 단계"가 Impl인지 먼저 확인한다.

## 확정 전제 (구현 시작 시점에 고정)
- ★ 절대 규칙 (날짜·근거 링크 — 말로만 두지 않고 `CLAUDE.md` + `project-memory/decisions/`에도 적는다)
- 언어/런타임 · 외부 시스템 · 실행 환경 제약
- 스모크 표준 대상(파일·테스트 계정·스테이징 환경 등)과 **원상복구 확인 절차**
- 독립 검수자와 호출 방법·모델 — `CLAUDE.md` "플랜 검수" 절에 있다. 이 사이클만 다르게 정할 때만 여기에 적는다
- 기간 한정 예외(사용자가 정한 것만)

## 진행 방식
항목 순서의 원문은 여기 한 곳에만 둔다. 한 항목 = 아래 1~10.

1. **맥락 잡기** — 이 README → progress("다음 착수 지점") · open-questions · handoff.md → checklist의 해당 항목 → 관련 설계.
2. **플랜 모드** — 조사 → 플랜 작성 → 플랜 검수(GO까지) → 사용자 승인. 플랜 파일 **마지막 줄**에 검수 기록 줄(`플랜 검수: GO — <검수자·회차> — 본문 <해시8>`).
   사용자가 정할 것은 텍스트로 한 번에 한두 개씩, 근거·장단점·권장과 함께 묻는다. 추론은 반영 전에 확인받는다.
3. **명세 고정** — 승인된 상세 명세(입출력 스키마, 상태·분기 규칙, 사용자 결정, 테스트 케이스, 스모크 기준)를 checklist 해당 항목에 적는다. progress에는 한 줄 요약 + 위치만.
4. **작업** — 계약(출력 스키마) 먼저, 가장 작은 흐름 하나를 처음부터 끝까지(수직 슬라이스) 먼저. 설계와 어긋나면 멈추고 사용자와 의논한다 — 구현이 설계와 다르면 `impl/`이 아니라 `../design/`을 고치고 plan까지 역전파한다.
   아직 구현되지 않은 단위는 건너뛰지 말고 그 앞에서 "미구현"을 알리며 멈추게 만든다.
5. **테스트** — 전체 스위트 결과(개수, 무작위 순서·시드를 쓰면 그 값)를 기록한다. 부작용 있는 스모크는 사전 상태 기록 → 승인된 스모크 → `finally` 정리 → 원상복구 확인. 되돌릴 수 없는 외부 쓰기는 실환경 스모크를 하지 않고 preflight로 미룬다.
6. **검수** — 독립 검수자(`CLAUDE.md` "플랜 검수" 절의 검수자·모델). P0·P1이 없을 때까지 반복하고, 재검수는 직전 지적 해소 + 회귀만 본다. 모델을 지정했다면 실행 기록으로 실제 모델을 확인한다.
7. **미결 정리** — 이 단계 ID로 인용할 수 있는 미결은 이 open-questions에, 아니면 `project-memory/open-questions.md`. 해소된 것은 지우고 gotchas/decisions로.
8. **로그** — progress 맨 위에 로그 추가, "다음 착수 지점" 갱신. `project-memory/log.md`에 의도 1~3줄.
9. **커밋·푸시** — GO 뒤에만, 사이클 브랜치에 한 커밋(산출물 + 문서 + 로그). GO 전 중간 상태는 `handoff.md`(커밋 안 함).
10. **핸드오프 점검** — 맥락 없는 서브에이전트에게 "이 README를 읽고 다음 항목 진행해줘"를 주고 실행 없이 계획만 보고받는다. 전부 만족해야 통과:
    ① 다음 항목을 `progress.md`의 "다음 착수 지점"과 같게 짚는다 ② 플랜 모드부터 들어간다고 답한다 ③ 먼저 읽을 문서·명세를 찾아낸다
    ④ 이미 끝난 항목·지운 ID·옛 명령을 현재 할 일로 읽지 않는다 ⑤ 작업 트리가 깨끗하다(항상 필수) — 원격이 있고 push가 허락된 프로젝트면 원격과 같아야 하고, 원격이 없으면 확인 대상이 아니며, 사용자가 push를 보류했다면 그 사실(이유·push 시점)이 `progress.md`나 `handoff.md`에 있으면 통과
    ⑥ 현재 브랜치가 진행 중 사이클 브랜치와 같고 사이클 README의 "현재 단계"가 점검한 단계와 같다.
    어긋나면 원인 문서를 고쳐 커밋·푸시하고 같은 점검을 다시 한다. 통과하면 progress에 한 줄 남기고 추가 커밋·푸시.

## 사이클 마무리 (Impl의 마지막 항목이 GO를 받고 커밋된 뒤)
승격 절차는 RMG "8단계 — 구현 중심 프로젝트 확장 (선택)"의 "사이클 생애 — 시작 · 진행 · 승격 · 폐기" 중 "승격"을 따른다(**완료 확인** — `design/map.md`의 모든 행이 design·impl `checklist.md`에서 `[x]`이거나 사용자 결정으로 범위에서 뺀 것 → 기본 브랜치를 `--no-commit` merge → `dev/global/` 반영(제거·대체된 global 단위는 `dev/global/retired/`로 퇴역) → 전체 테스트 + 승격 검수 → GO 뒤 커밋 → 사용자 허락 후 기본 브랜치 병합 → 릴리즈 여부 확인).
