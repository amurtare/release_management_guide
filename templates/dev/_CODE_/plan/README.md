## 진행 방식
항목 순서의 원문은 여기 한 곳에만 둔다(CLAUDE.md는 여기를 가리키기만 한다). 한 항목 = 아래 1~9.

1. **맥락 잡기** — 이 README → progress("다음 착수 지점") · open-questions · handoff.md → checklist의 해당 항목 → 관련 설계.
2. **플랜 모드** — 조사 → 플랜 작성 → 플랜 검수(GO까지) → 사용자 승인. 플랜 파일 **마지막 줄**에 검수 기록 줄을 쓴다
   (`플랜 검수: GO — <검수자·회차> — 본문 <해시8>`, 해시는 훅이 차단할 때 알려 준다). 사용자가 정할 것은 텍스트로 한 번에 한두 개씩, 근거·장단점·권장과 함께 묻는다. 추론은 반영 전에 확인받는다.
3. **명세 고정** — 승인된 결정을 `overview.md`·`checklist.md`에 적는다. progress에는 한 줄 요약 + 위치만. (저장소 밖 플랜 파일은 다음 세션이 못 본다.)
4. **작업** — 개요·확정 결정을 쓴다. 에이전트의 추론은 확정이 아니다. 설계 내용은 쓰지 않고 `design/checklist.md`의 단위별 "결정할 것"으로 넘긴다.
5. **검수** — 독립 검수자(`CLAUDE.md` "플랜 검수" 절의 검수자·모델). P0·P1이 없을 때까지 반복하고, 재검수는 직전 지적 해소 + 회귀만 본다. 모델을 지정했다면 실행 기록으로 실제 모델을 확인한다.
6. **미결 정리** — 이 단계 ID로 인용할 수 있는 미결은 이 단계 open-questions에, 아니면 `project-memory/open-questions.md`. 해소된 것은 지우고 gotchas/decisions로.
7. **로그** — progress 맨 위에 로그 추가, "다음 착수 지점" 갱신. `project-memory/log.md`에 의도 1~3줄.
8. **커밋·푸시** — GO 뒤에만, 사이클 브랜치에 한 커밋. GO 전 중간 상태는 `handoff.md`(커밋 안 함).
9. **핸드오프 점검** — 맥락 없는 서브에이전트에게 "이 README를 읽고 다음 항목 진행해줘"를 주고 실행 없이 계획만 보고받는다. 전부 만족해야 통과:
   ① 다음 항목을 `progress.md`의 "다음 착수 지점"과 같게 짚는다 ② 플랜 모드부터 들어간다고 답한다 ③ 먼저 읽을 문서·명세를 찾아낸다
   ④ 이미 끝난 항목·지운 ID·옛 명령을 현재 할 일로 읽지 않는다 ⑤ 작업 트리가 깨끗하다(항상 필수) — 원격이 있고 push가 허락된 프로젝트면 원격과 같아야 하고, 원격이 없으면 확인 대상이 아니며, 사용자가 push를 보류했다면 그 사실(이유·push 시점)이 `progress.md`나 `handoff.md`에 있으면 통과
   ⑥ 현재 브랜치가 진행 중 사이클 브랜치와 같고 사이클 README의 "현재 단계"가 점검한 단계와 같다.
   어긋나면 원인 문서를 고쳐 커밋·푸시하고 같은 점검을 다시 한다. 통과하면 progress에 한 줄 남기고 추가 커밋·푸시.

## 단계 전환 (Plan → Design)
게이트: 확정 목록 · `design/checklist.md`의 단위별 상세화 대기 목록 · 폐기 가설 명시 · 진입점 README.
남은 미결은 `design/open-questions.md`로 이관하고 여기에는 `[이관 YYYY-MM-DD → design/open-questions.md <ID>]`를 남긴다. 사이클 README의 "현재 단계"를 갱신한다.
