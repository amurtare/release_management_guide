# <코드> Design 미결·미검증 목록

## 운영 규칙
- **무엇을 넣나**: 확보할 자료·실측, 남은 결정 논점, 그리고 ② 검수의 빈틈 ③ 외부 규칙 의존 가정 ④ 부작용 때문에 미룬 실행(preflight) ⑤ 미이행
- **경계**: 이 단계의 단위·항목 ID로 인용할 수 있는 것만. 아니면 `project-memory/open-questions.md`
- **언제**: 각 항목을 마칠 때(커밋 전) — 새 항목 추가 + 해소된 항목 정리
- **해소되면**: 항목을 지우고 결과를 `project-memory/gotchas.md`(사실) 또는 `project-memory/decisions/`의 새 결정 파일(정책 변경 — 결정 파일 본문은 수정하지 않고, 뒤집히면 새 파일 + 옛 파일 맨 위 `Superseded by` 한 줄)로 옮긴다. progress.md에는 건수와 ID만 적는다.
- **단계 전환 때**: 남은 항목은 다음 단계 장부로 옮기고 여기에 `[이관 YYYY-MM-DD → <단계>/open-questions.md <ID>]`를 남긴다.
- **ID**: 구획 문자 + 번호(`B3`). 지운 ID는 재사용하지 않는다.
