# <코드> 설계 지도 (to-be — 이 사이클 구현의 기준)

> 이 사이클 설계의 단일 소스다. 단위마다 한 행. 도식으로 그릴 때는 지금의 흐름·조건만 담고 이력·근거는 md에만 둔다.
> **"구현 구분" 열이 Design → Impl 계약이다.** `../impl/checklist.md`는 이 열을 Phase로 편성한 것이며, 이 칸에는 "만들 모듈·API와 그 입출력 계약"을 적는다.
> `(워크플로형)` 열은 워크플로형 프로젝트에서만 쓴다(사람이 개입하는 지점은 처리 칸에 `★사용자 개입:`으로 표시). 병렬 단위로 이뤄진 서비스·라이브러리형은 두 열을 지우고 의존 관계만 적는다.
> "global 관계" 값: `신규` / `global/<…> 변경` / `제거: <global 단위 ID>` / `대체: <옛 ID> → <새 ID>`. 제거·대체는 승격 때 그 global 단위가 `dev/global/retired/`로 퇴역한다.
> 외부 조망도(화이트보드 사진·위키 흐름도)는 비규범이다. 외부에 부작용을 내거나 안전 검사·사람 확인·대기를 맡은 단위를 합치거나 지우는 것은 별도 결정 없이 금지(순수 계산 단위끼리 합치는 것만 허용).
